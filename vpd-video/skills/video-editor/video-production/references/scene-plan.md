# Current story and scene handoff

Use this when taking a narrated story into production or revising its story. It can be supplied by a writer or prepared with the user; it does not require another installed skill. During brainstorm, discuss these fields without writing files.

## Authority and writing loop

Maintain one CURRENT document per role (clean narration, scene plan, vocabulary) and an index linking the current set. A replaced writing document gets `SUPERSEDED BY [replacement]`; preserve it as history. For an accepted change, update the current narration/plan and rejected-directions list together. Do not import a superseded flash, line, sound cue or claim just because it appears in an older treatment.

Start with the person's own conversational explanation. Draft for speaking, record a scratch read, transcribe locally, compare, revise and speak again. Preserve ad-libs that keep the intended meaning; correct recognition errors in a working copy. A good rehearsal can be the selected production take. Timing comes from that performance, not a guessed word count.

Every script delivery reports a tool-counted narration-only word count and measured duration, naming the recording/window and whether it is a rehearsal or selected take. Without a read, say measured duration is unavailable; an estimate must be labeled as an estimate, never passed off as measured. Measure again when wording/performance changes. Keep production directions out of the counted narration.

## Handoff header

```text
CURRENT — revision, date, owner
Current narration: project-relative path
Current scene plan: project-relative path
Vocabulary: project-relative path
Selected read: original source, in/out, transcript and corrected working copy
Measurement: narration word count; read duration; measurement source/method
Audience / takeaway / ending:
Traveling fact: the specific knowledge or change that must remain visible
Truth notes: what the picture must not imply, with named supporting evidence
Do not: rejected directions and reasons; add accepted rejections here
Settled choices / open questions:
```

The vocabulary file records canonical spellings, likely recognition variants and contextual distinctions. Use generic project terms; private creator examples and preferences belong in the supplied creator profile. Vocabulary is evidence for judgment, not a global find-and-replace instruction. Keep raw transcripts unchanged.

## Per-scene fields

| Field | Purpose |
| --- | --- |
| Stable scene ID and revision | Feedback survives retiming and scene reordering. |
| Purpose / viewer takeaway | What viewers should understand by the end. |
| Narration anchor and measured range | Exact spoken phrase plus source/output timing when available. |
| Traveling fact entering/leaving | The same lesson, object or change across the relevant scenes. |
| Visible action and exact screen copy | What demonstrates the point, including readable names and values. |
| Truth notes / evidence | What the action can imply; what it must not imply. |
| Required assets / references / layers | Accepted identities, objects, editable type and provenance. |
| Opening / settled / exit states | Observable poses, motion and transition, including persistent objects. |
| Reading hold | The actual copy/object that needs time; reserve its hold before animation. |
| Landscape / portrait layouts | Placement, reading order and safe areas for both requested formats. |
| Audio intent | Voice anchor, music continuity, purposeful sound and forbidden cues. |
| Settled / exploratory / rejected | What can change, and what has already been ruled out. |

Do not prescribe pixels the story does not depend on. Do specify an essential handoff: for example, a first worker discovers a limit, the record receives that exact limit, and the next worker visibly uses it. A changing version number alone does not show that learning transferred.

## Two separate audits

**Payoff:** Can a cold viewer say what changed, who benefits and why? Does the picture show the traveling fact at each necessary step? Does the ending have enough reading time?

**Truth:** Does the visual metaphor imply unsupported product behavior, permissions, guarantees or evidence? Each factual/outcome line must be a properly scoped story event, supported by named project evidence, or removed. Do not relabel an unsupported real product claim as fiction to retain it.

Ready for detailed production: the story survived a spoken read, its payoff can be seen, picture and narration pass the truth audit, the wording sounds like the creator, duration is measured, and the essential visuals are feasible. A rough pivotal-scene test can resolve feasibility before all art exists.
